1. How Coypu is versioned

Coypu has been developed in the open since January 2021 on a rolling basis. The working branch is master and there is a single tag, v1.0-withoutRecording, so the commit history is the real changelog.

WhereWhat it tells you
Commit historyEvery change
IssuesKnown problems and what is being worked on
RepositorySource, README and installation notes
Music with PharoThis site, with a development blog
Coypu is master, Phausto is main The two sibling packages use different default branch names. Getting it wrong produces a Metacello error that does not make the cause obvious.

1.1 Pinning a version

For a piece you intend to perform again, pin the commit rather than tracking the branch:

Metacello new
  baseline: 'Coypu';
  repository: 'github://lucretiomsp/coypu:<commit-sha>';
  load.
Pin both Coypu's baseline pulls in Phausto, so a reproducible setup means pinning that too. Record both commits alongside the piece.

2. Recent development

Rather than a version-by-version list, the themes the recent history shows:

ThemeWhat changed
Cycle-based playbackA second playback model alongside the original step-based one: SequencerPlayer as a Strategy, with SequencerPlayerLinear and SequencerPlayerCyclic. See Player API §5.
Mondo mini-notationA TidalCycles-style string notation with grouping, alternation and per-cycle divisors, built on CoyArc, CoyEvent and MondoAlternation. See Rhythms: Advanced §4.
Note-name parsingasMidiNote, accepting note names and both standard and TidalCycles accidental spellings.
TimingThe transport moved to an accumulating monotonic microsecond clock, so it does not drift, with event sending forked at lower priority.
Phausto integrationPer-sound gate and note destinations, so one Sequencer can address several instruments inside one DSP.
TestsFifteen test classes, including parser and dispatch tests for the newer cyclic machinery.

3. Known quirks in the current source

Behaviours that will cost you time if you meet them unprepared. All are verified against the current master.

WhereBehaviour
Integer>>bomba:Never assigns its pattern variable, so it always raises. Plain bomba is fine — Rhythm Library
Sequencer>>squiz:Writes to the 'room' key, so it sets reverb and overwrites room: — Effects §5
Performance>>unmute: / unsolo:Discard their argument and restore the whole snapshot — Performing §4.1
asMidiNN vs asMidiNoteDisagree by an octave: 'c4' is 72 and 60 respectively — Operators §8
Sequencer>>sizeAnswers the trigger count, not the pattern length
adowa / sikyiIdentical patterns, so the two selectors sound the same
Scale pentaMinor / yoIdentical interval arrays
Scale minorThe only scale including its octave, so it has 8 elements where the others have 7
disortion:A misspelt twin of distortion:; both work
Integer>>aksak commentSays “multiple of 8” but the pattern is 10 steps
Documented, not worked around None of these is patched in the manual's examples. Where one bites, the page that covers that area says so and gives the alternative.

6. Troubleshooting

Metacello cannot find the baseline

The branch is master — §1.

Code from an older tutorial no longer runs

Check §3 first; several behaviours are surprising rather than broken.

Metacello keeps loading a stale version

The repository is cached under pharo-local/iceberg. Delete the cached checkout or pull master through Iceberg.

A feature in this manual is missing from my image

Your copy predates it. Update, or check the commit history — §1.

Something broke after updating

Open an issue with the snippet and the commit you moved to — see Community.
